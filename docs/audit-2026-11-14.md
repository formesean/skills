# Engineering skills audit — 2026-11-14

Reviewed baseline: [`d3b07fb939785f636bd6e0f4e0b1bfb2b4dcb3e0`](https://github.com/formesean/skills/tree/d3b07fb939785f636bd6e0f4e0b1bfb2b4dcb3e0).
Scope: all ten skills, repository guides, README, and three manifests. The baseline
has no runtime scripts, agent definitions, persistent-state implementation, or tests.
This is a source audit of instructions; downstream incidents were not reproduced.

## Assessment

The strongest features are clear task ownership, attention to evidence, minimal diffs,
and separation of stakeholder replies from implementation. Preserve those. The main
weakness is excessive absolute rules: they sometimes conflict with each other, suppress
relevant evidence, or force users through unnecessary turns. A skill cannot add durable
memory by promising to remember; state storage and resume validation need implementation.

## Architecture and tradeoffs

- Skills define procedures. The host supplies tools, permissions, context compaction,
  model selection, and execution. The local harness supplies checkpoints and validation.
- Keep a main coordinator and optional explorer/reviewer/verifier workers. A role prompt
  does not enforce read-only access. Claude explorer/reviewer omit shell/write tools;
  Codex role instructions inherit host permissions and require appropriate sandboxing.
- Save small task state near its repository, outside tracked files. Use claims with source
  pointers, explicit unknowns, and next actions rather than transcripts. Durable knowledge
  belongs in accepted project documentation with provenance and invalidation conditions.
- State fingerprints cover HEAD, branch, tracked/index diffs, and untracked content.
  They do not certify environment, ignored configuration, dependencies, submodules, remote
  services, or truthful caller-reported check results. Revalidate these separately.
- The harness intentionally does not implement API calls, automatic tool execution, a
  vector database, or a new agent framework. Use existing hosts; add machinery only when
  evaluations demonstrate a missing capability. No zero-risk or fully autonomous claim.

## Validation and rollout

Executed: repository format/budget/manifest/agent alignment validation; twelve isolated
checkpoint tests; two fresh-context scenario probes. Python 3.11+ standard library only.
See `evals/results-2026-11-14.md` for scenario details and limitations. Git diff whitespace
checking and YAML/TOML parsing are also part of final review.

Not yet demonstrated: all twelve behavior scenarios, repeated baseline/candidate model
runs, held-out real tasks, total token reduction, full Codex/Claude plugin installation,
or cross-platform execution. Local Codex command help was inspected; Claude was absent.

Roll out as a draft PR. Review the change from unconditional “never push” to respecting
explicit publication authorization, then run remaining scenarios on both preferred
clients before treating this as a stable release. Keep independent task success,
false-claim rate, scope violations, user interruptions, latency, and token metrics.
Use small batches of real tickets; rollback by reverting the PR if regressions appear.

An independent review of the new checkpoint code reproduced two defects: indented
serialization could exceed the read limit, and extra stored metadata could overwrite
the computed freshness label. Both were fixed and covered by new regression tests.

## Standards and primary references

Checked 2026-11-14. Recommendations are adapted to this repository; they are not claims
that any one source mandates this architecture.

- [Agent Skills specification](https://agentskills.io/specification): required name and
  description, naming/length constraints, portable directory format, progressive loading.
  The local validator intentionally enforces a narrower single-line frontmatter format;
  it is not a general-purpose Agent Skills conformance checker.
- [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents):
  keep relevant context small, retrieve when needed, compact useful state, isolate noisy
  investigation. This motivates bounded evidence and checkpoints, not blind truncation.
- [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): project
  TOML definitions, scoped task handoffs, host inheritance, and additional token costs.
  No unsupported claim that a role file overrides sandbox/approval settings.
- [Claude Code subagents](https://code.claude.com/docs/en/sub-agents): Markdown agent
  definitions, explicit tool sets, separate worker context and capability restrictions.
- [Claude plugin reference](https://code.claude.com/docs/en/plugins-reference): plugin
  component layout. Host-specific agents remain distinct from portable skill bodies.
